# ナイトだんどり　本番サーバー配備手順

対象：`https://dandori.olivia.ai-labo.cloud`（サーバーの nginx が https を受けて `127.0.0.1:8032` へ転送）
DB：`dandoriolivia`（ユーザー `ai_labo_dbuser`）

```
 ブラウザ / LINE
     │ https://dandori.olivia.ai-labo.cloud
     ▼
 サーバーの nginx（https・設定済み）
     │ 127.0.0.1:8032
     ▼
 docker compose（server/compose.yaml）
   gateway   画面（1_画面）と API の入口
   rest      データの受け口（PostgREST）
   auth      ログイン（GoTrue）
   storage   ファイル（server/data/storage に保存）
   functions 3_サーバー をそのまま実行
     │
     ▼
 PostgreSQL  dandoriolivia
```

画面と API が同じアドレスなので、`config.js` は起動時に自動でこのサーバー向けになります
（リポジトリの `config.js` は書き換えません）。

---

## 0. サーバーに必要なもの

- Docker と docker compose（`docker compose version` で確認）
- `git`、`curl`、`openssl`

## 1. DB の権限を確認（superuser で1回だけ）

`ai_labo_dbuser` が、Supabase と同じ役割（anon / authenticated など）を作れる必要があります。

```sql
-- DB の持ち主が ai_labo_dbuser になっていること
ALTER DATABASE dandoriolivia OWNER TO ai_labo_dbuser;
-- 役割を作れるように
ALTER ROLE ai_labo_dbuser CREATEROLE;
-- Supabase からデータを移すときだけ（PostgreSQL 15 以上）
GRANT SET ON PARAMETER session_replication_role TO ai_labo_dbuser;
```

RDS の場合は、マスターユーザーで同じことをします（マスターユーザーは最初から CREATEROLE を持っています）。

### DB が同じサーバーにある場合

コンテナから見ると、サーバー自身は `host.docker.internal` です（`.env` の既定値）。
PostgreSQL がコンテナからの接続を受けるように、2か所を確認します。

- `postgresql.conf`：`listen_addresses = '*'`（または `'localhost,172.17.0.1'`）
- `pg_hba.conf`：コンテナの範囲を許可
  ```
  host  dandoriolivia  all  172.16.0.0/12  scram-sha-256
  ```
- 変更したら `sudo systemctl reload postgresql`

※ ポート 5432 をインターネットに開ける必要はありません（セキュリティグループは閉じたままで大丈夫です）。

### DB が RDS の場合

`.env` の `DB_HOST` に RDS のエンドポイント、`DB_SSLMODE=require` を入れます。
RDS のセキュリティグループで、このサーバーからの 5432 を許可してください。

## 2. ソースを置いて、設定を作る

```bash
git clone https://github.com/emcyrup/dandori.git
cd dandori/server
./setup.sh            # .env を作り、鍵とパスワードを自動で入れる
vi .env               # DB_PASSWORD などを入れる（下の表）
./setup.sh            # 「準備できました」と出れば OK
```

| 項目 | 入れるもの |
|---|---|
| `DB_PASSWORD` | `ai_labo_dbuser` のパスワード |
| `DB_HOST` / `DB_SSLMODE` | 同じサーバーなら既定のまま。RDS ならエンドポイントと `require` |
| `SMTP_*` | パスワード再設定・招待メール用（SES の SMTP 認証情報と、送り主アドレス） |
| `ANTHROPIC_API_KEY` など | Supabase の Functions Secrets に入れていた鍵（使うものだけ） |

`.env` には鍵が入ります。`chmod 600` 済み・git には入りません。人に送らないでください。

## 3. 配備する

```bash
./deploy.sh --init
```

1. コンテナを作る
2. DB に Supabase と同じ役割・権限を作る（`bootstrap`）
3. 起動（ログインとファイルの部品が、自分のテーブルを作る）
4. `2_データベース` の SQL を全部流す → 仕上げ（`post.sql`）
5. 動作確認（下のように全部 200 なら成功）

```
== 動作確認
   入口     200
   ログイン 200
   データ  200
   ファイル 200
   公開URL  200
```

## 4. 最初の店長を作る（新しく始める場合）

```bash
set -a; . ./.env; set +a
curl -X POST "$SITE_URL/auth/v1/admin/users" \
  -H "Authorization: Bearer $SERVICE_ROLE_KEY" -H "apikey: $SERVICE_ROLE_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"email":"owner@example.jp","password":"（初期パスワード）","email_confirm":true}'

docker compose run --rm migrator sql "select name, role from app.link_staff('owner@example.jp', '鈴木', 'owner')"
```

デモデータを入れるなら `docker compose run --rm migrator demo`。

## 4'. Supabase から移す場合

1. `.env` の `SOURCE_DB_URL` に、Supabase → Project Settings → Database → Connection string →
   **Session pooler** の接続文字列を入れる
2. 移行中は Supabase 側の入力を止めてもらう
3. データ（ログインのユーザーとパスワードも）を移す
   ```bash
   docker compose run --rm migrator import
   ```
4. ファイルを移す（Node.js 18 以上がある端末で）
   ```bash
   SRC_URL=https://mfsvfolyrkrpribnwvcl.supabase.co SRC_KEY=<Supabase の service_role キー> \
   DST_URL=https://dandori.olivia.ai-labo.cloud DST_KEY=<.env の SERVICE_ROLE_KEY> \
   node ../aws/tools/copy-storage.mjs
   ```
5. `.env` の `SOURCE_DB_URL` を空に戻す

切り替え後は鍵が変わるので、全員いちどログインし直しです（パスワードは同じ）。

## 5. 外のサービスの設定

- **LINE Developers** → Webhook URL（法人ごと）
  `https://dandori.olivia.ai-labo.cloud/functions/v1/line-webhook?t=（法人ID）`
- **送信箱の自動送信**（5分ごと）を使うなら `.env` に `COMPOSE_PROFILES=outbox` → `./deploy.sh`

## サーバーの nginx の設定（確認）

8032 へ転送している `location` に、次が入っているか確認してください。
ファイルのアップロード（最大 50MB）と、AI の下書き（最大 150 秒）のためです。

```nginx
location / {
    proxy_pass http://127.0.0.1:8032;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    client_max_body_size 50m;
    proxy_read_timeout 150s;
}
```

## ふだんの運用

| やりたいこと | コマンド（`server/` で） |
|---|---|
| 画面や 3_サーバー を直した | `git pull && ./deploy.sh` |
| SQL を足した | `git pull && ./deploy.sh --sql 新しいファイル.sql` |
| SQL を1文流す | `docker compose run --rm migrator sql "select ..."` |
| ログを見る | `docker compose logs -f --tail 100` |
| 止める / 動かす | `docker compose stop` / `docker compose up -d` |

### バックアップ（必ず設定してください）

- DB：`pg_dump -Fc dandoriolivia > dandori_$(date +%F).dump` を毎日（cron）
- ファイル：`server/data/storage/` をまるごと
- 鍵：`server/.env`（無くすと、全員のログインが切れます）
