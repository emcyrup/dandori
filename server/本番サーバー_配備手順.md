# ナイトだんどり　本番サーバー配備手順

対象：`https://dandori.olivia.ai-labo.cloud` → サーバーの nginx（https）→ `127.0.0.1:8032`
サーバー：Ubuntu / Node 22 / PostgreSQL 18、**sudo なし・Docker なし**（ホームディレクトリ内だけで動かす）
DB：`dandoriolivia`（ユーザー `ai_labo_dbuser`）

```
 ブラウザ / LINE
     │ https://dandori.olivia.ai-labo.cloud
     ▼
 サーバーの nginx（https・提供元が管理）
     │ 127.0.0.1:8032
     ▼
 PM2 が動かすプロセス（~/dandori/server）
   gateway    入口。画面（1_画面）を出し、API を下の部品へ振り分ける   Node
   rest       データの受け口（PostgREST、単体バイナリ）                 :38032
   auth       ログイン（GoTrue、単体バイナリ）                          :38033
   storage    ファイル置き場（server/data/storage に保存）              Node :38034
   fn-*       3_サーバー の5つの関数（Deno）                            :38041〜
   outbox     送信箱を5分ごとに送る（任意）
     │
     ▼
 PostgreSQL（同じサーバー）dandoriolivia
```

Supabase の `supabase.js`（画面側）はそのまま使えます。`config.js` の接続先は、入口が自動でこのサーバーに向けて出すので、
リポジトリの `config.js` を書き換える必要はありません。

### Supabase との違い

| | Supabase | このサーバー |
|---|---|---|
| ログイン / データの受け口 | クラウド | 同じ部品（GoTrue / PostgREST）を手元で動かす |
| ファイル置き場 | Storage | 小さな自前の実装（`server/storage`）。アプリが使う操作だけ対応 |
| Edge Functions | Deno（クラウド） | Deno（単体バイナリ）で同じコードを動かす |
| 定期送信（pg_cron） | DB 内 | PM2 の5分ごと起動（`.env` の `OUTBOX=1`） |
| 管理画面 / SQL Editor | あり | `./db.sh sql "…"` / `./db.sh psql` |
| service_role の RLS 素通り | あり | 無いので、SQL を流すたびに `post.sql` で代わりの許可を足す（`db.sh schema` が自動で行う） |

## 0. 先に、DB 管理者（サーバー提供元）に頼むこと

配布された `ai_labo_dbuser` は役割（ロール）を作れないので、**`db/依頼_DB権限.sql`** を渡して、
次のどちらかをお願いしてください。

- A（簡単）：`ALTER ROLE ai_labo_dbuser CREATEROLE;` を一時的に付けてもらう（初期設定後に外して可）
- B：`db/依頼_DB権限.sql` を superuser で流してもらう（パスワード3つは `.env` の値を別途伝える）

あわせて確認：`dandoriolivia` の持ち主が `ai_labo_dbuser` であること、サーバーから
`github.com`・`esm.sh`・`api.line.me`・各 AI の API に外向きの通信ができること。

## 1. 部品を入れる（sudo 不要・5分）

```bash
cd ~ && git clone https://github.com/emcyrup/dandori.git && cd dandori/server
./install.sh
```

GitHub から PostgREST・GoTrue・Deno の単体バイナリ（版固定）を `bin/` に入れ、`npm install` で PM2 と pg を入れます。

## 2. 設定を作る

```bash
./setup.sh          # .env を作り、鍵とパスワードを自動生成
vi .env             # DB_PASSWORD を入れる（配布資料の DB パスワード）。SMTP・AI の鍵も使うなら
./setup.sh          # 「準備できました」と出れば OK
```

`.env` には鍵が入ります（`chmod 600` 済み・git には入りません）。

## 3. 配備する

```bash
./deploy.sh --init
```

1. DB の権限を確認（足りなければ、何を頼むか表示して止まる）
2. Supabase と同じ役割・権限を作る（`bootstrap`）、ファイル置き場の表を作る
3. ログイン（GoTrue）を先に起動して、自分の表を作らせる
4. `2_データベース` の SQL を全部流す → 仕上げ（`post.sql`）
5. 全部起動、PM2 に保存、再起動後の自動起動を crontab に登録
6. 動作確認（下のように全部 200 なら成功）

```
== 動作確認
   入口       200
   ログイン   200
   データ     200
   ファイル   200
   関数       200
   公開URL    200
```

## 4. 最初の店長を作る（新しく始める場合）

```bash
./db.sh demo                                              # デモデータ（任意）
./db.sh user-add owner@example.jp '初期パスワード' 鈴木 owner  # ログイン + スタッフ登録
```

## 4'. Supabase から移す場合

1. `.env` の `SOURCE_DB_URL` に Supabase の **Session pooler** 接続文字列を入れる
2. 移行中は Supabase 側の入力を止めてもらう
3. `./db.sh import`（ログインのユーザーとパスワード・全データ。51テーブルで件数を照合済み）
   ※ `session_replication_role` の権限が無いと止まります。その場合は依頼 SQL の該当行を管理者に頼んでください
4. ファイルを移す：
   ```bash
   SRC_URL=https://mfsvfolyrkrpribnwvcl.supabase.co SRC_KEY=<Supabase の service_role> \
   DST_URL=https://dandori.olivia.ai-labo.cloud DST_KEY=<.env の SERVICE_ROLE_KEY> \
   node ../aws/tools/copy-storage.mjs
   ```
5. `.env` の `SOURCE_DB_URL` を空に戻す

切り替え後は鍵が変わるので、全員いちどログインし直しです（パスワードは同じ）。

## 5. 外のサービスの設定

- LINE Developers → Webhook URL：`https://dandori.olivia.ai-labo.cloud/functions/v1/line-webhook?t=（法人ID）`
- 送信箱の自動送信を使うなら `.env` に `OUTBOX=1` → `./deploy.sh`
- 提供元の nginx 側（8032 への転送）に次があるか確認してもらう：
  `client_max_body_size 50m;`（ファイルのアップロード）、`proxy_read_timeout 150s;`（AI の下書き）、
  `proxy_set_header X-Forwarded-Proto $scheme;`

## ふだんの運用（`~/dandori/server` で）

| やりたいこと | コマンド |
|---|---|
| 画面や 3_サーバー を直した | `git pull && ./deploy.sh` |
| SQL を足した | `git pull && ./deploy.sh --sql 新しいファイル.sql` |
| SQL を1文流す / 対話 | `./db.sh sql "select …"` / `./db.sh psql` |
| 状態を見る | `./deploy.sh --status` |
| ログを見る | `./node_modules/.bin/pm2 logs` または `tail -f logs/*.log` |
| 止める | `./deploy.sh --stop` |

バックアップ：DB は提供元が自動ダンプ + AWS Backup（7日）を行う方針とのこと。
**`server/data/storage/`（ファイル）と `server/.env`（鍵。無くすと全員ログイン不可）** は、こちらで控えを取ってください。

## 困ったとき

- `関数 502`：Deno が初回に esm.sh からライブラリを取得中。1〜2分待って `./deploy.sh --status`。
  それでも駄目なら `tail logs/fn-ai.log`（外向き通信が止められていないか）
- `ログイン 502`：`tail logs/auth.log`。DB の役割 `supabase_auth_admin` のパスワードが `.env` と違うことが多い
- ポートがぶつかる（`EADDRINUSE`）：`.env` の `REST_PORT` などを変えて `./deploy.sh`
- `role "anon" does not exist`：手順 0 がまだ
