# ナイトだんどり　本番サーバー配備手順

対象：`https://dandori.olivia.ai-labo.cloud` → サーバーの nginx（https）→ `127.0.0.1:8032`
サーバー：Ubuntu / Node 22 / PostgreSQL 18、**sudo なし・Docker なし**（ホームディレクトリ内だけで動かす）
DB：`dandoriolivia`（ユーザー `ai_labo_dbuser`）

```
 ブラウザ / LINE
     │ https://dandori.olivia.ai-labo.cloud
     ▼
 サーバーの nginx（https・提供元が管理）
     │ 127.0.0.1:8032
     ▼
 PM2 が動かすプロセス（~/dandori/server）
   gateway    入口。画面（1_画面）を出し、API を下の部品へ振り分ける   Node
   rest       データの受け口（PostgREST、単体バイナリ）                 :38032
   auth       ログイン（GoTrue、単体バイナリ）                          :38033
   storage    ファイル置き場（server/data/storage に保存）              Node :38034
   fn-*       3_サーバー の5つの関数（Deno）                            :38041〜
   outbox     送信箱を5分ごとに送る（任意）
     │
     ▼
 PostgreSQL（同じサーバー）dandoriolivia
```

Supabase の `supabase.js`（画面側）はそのまま使えます。`config.js` の接続先は、入口が自動でこのサーバーに向けて出すので、
リポジトリの `config.js` を書き換える必要はありません。

### Supabase との違い

| | Supabase | このサーバー |
|---|---|---|
| ログイン / データの受け口 | クラウド | 同じ部品（GoTrue / PostgREST）を手元で動かす |
| ファイル置き場 | Storage | 小さな自前の実装（`server/storage`）。アプリが使う操作だけ対応 |
| Edge Functions | Deno（クラウド） | Deno（単体バイナリ）で同じコードを動かす |
| 定期送信（pg_cron） | DB 内 | PM2 の5分ごと起動（`.env` の `OUTBOX=1`） |
| 管理画面 / SQL Editor | あり | `./db.sh sql "…"` / `./db.sh psql` |
| service_role の RLS 素通り | あり | 無いので、SQL を流すたびに `post.sql` で代わりの許可を足す（`db.sh schema` が自動で行う） |

## 0. 先に、DB 管理者（サーバー提供元）に頼むこと

配布された `ai_labo_dbuser` は役割（ロール）を作れないので、**`db/依頼_DB権限.sql`** を渡して、
次のどちらかをお願いしてください。

- A（簡単）：`ALTER ROLE ai_labo_dbuser CREATEROLE;` を一時的に付けてもらう（初期設定後に外して可）
- B：`db/依頼_DB権限.sql` を superuser で流してもらう（パスワード3つは `.env` の値を別途伝える）

あわせて確認：`dandoriolivia` の持ち主が `ai_labo_dbuser` であること、サーバーから
`github.com`・`esm.sh`・`api.line.me`・各 AI の API に外向きの通信ができること。

## 店舗ごとの環境について

1店舗 = GitHub の Environment 1つ ＝ サーバー上のフォルダ1つ（`~/dandori-<店舗>`）＝ DB 1つ です。
店舗だけの設定（お店・メニュー・キャスト・給与）は `stores/<店舗>/store.sql` に置き、
全店共通の `2_データベース` のあとに流れます。新しい店舗の増やし方は `stores/README.md` を見てください。
いま配備する店舗は **olivia** です。

## 1. GitHub Actions で配備する（ふだんはこれだけ）

`main` に変更が入ると、`.github/workflows/deploy-server.yml` がサーバーへ SSH でつなぎ、
ソースを送って `install.sh → setup.sh → deploy.sh --auto` を実行します（初回は自動で `--init` 相当）。
`2_データベース` に変更があった push では、SQL も流します。

### 初回だけ：GitHub に店舗の Environment を作り、鍵と設定を登録する

リポジトリの **Settings → Environments → New environment**。名前は店舗名（`olivia`）。その中に：

| 種類 | 名前 | 値 |
|---|---|---|
| Secret | `SERVER_SSH_KEY` | 配布された秘密鍵 `id_rsa_3piece4-prod.pem` の中身（`-----BEGIN` から `END-----` まで全部） |
| Secret | `DB_PASSWORD` | 配布資料の DB パスワード |
| Secret（任意） | `SMTP_USER` `SMTP_PASS` `SMTP_ADMIN_EMAIL` | パスワード再設定メールを使うなら（SES の SMTP 認証情報） |
| Secret（任意） | `ANTHROPIC_API_KEY` `GEMINI_API_KEY` `OPENAI_API_KEY` `PIXABAY_API_KEY` | Supabase の Functions Secrets に入れていた鍵 |
| Variable | `SERVER_HOST` `SERVER_USER` `SERVER_DIR` `SITE_URL` `LISTEN_PORT` `DB_NAME` | olivia は既定値あり（`15.168.86.215` / `3piece_prod4` / `dandori-olivia` / `https://dandori.olivia.ai-labo.cloud` / `8032` / `dandoriolivia`）。2店舗目からは必ず入れる |

配備する店舗の一覧は、リポジトリの Variables の `STORES`（例 `olivia,second`）。無ければ `olivia` だけ。
**Actions → deploy-server → Run workflow** で手動実行できます（店舗名を入れればその店舗だけ、`run_sql` にチェックで SQL も流す）。

### 実行の流れ（ログで見える順）

1. 文法チェック
2. SSH 接続の確認（`接続OK: 3piece_prod4@…` と出る）
3. ソースを送る（`~/dandori-olivia` に展開。`server/.env` `data/` `logs/` `bin/` は残る）
4. Secrets を `.env` に流し込む → `setup.sh`（鍵は初回に自動生成、2回目からは変えない）
5. `install.sh`（部品の取得。初回だけ数分）
6. `deploy.sh --auto`（初回：DB 初期設定 → 起動 → SQL 全部（共通 → 店舗） → 確認）
7. 公開 URL が 200 を返すか

手順 0 の DB 権限が無いと、6 で「`db/依頼_DB権限.sql` を管理者に」と出て止まります。

## 2. 手で配備する場合（SSH で入って）

```bash
cd ~/dandori-olivia/server   # GitHub Actions が送ったもの（無ければ git clone して .env の STORE を書く）
./install.sh
./setup.sh && vi .env && ./setup.sh     # DB_PASSWORD などを入れる
./deploy.sh --init
```

動作確認が全部 200 なら成功です。


## 3. 最初の店長を作る（SSH で入って1回だけ）

```bash
./db.sh demo                                              # デモデータ（任意）
./db.sh user-add owner@example.jp '初期パスワード' 鈴木 owner  # ログイン + スタッフ登録
```

## 4. 外のサービスの設定

- LINE Developers → Webhook URL：`https://dandori.olivia.ai-labo.cloud/functions/v1/line-webhook?t=（法人ID）`
- 送信箱の自動送信を使うなら `.env` に `OUTBOX=1` → `./deploy.sh`
- 提供元の nginx 側（8032 への転送）に次があるか確認してもらう：
  `client_max_body_size 50m;`（ファイルのアップロード）、`proxy_read_timeout 150s;`（AI の下書き）、
  `proxy_set_header X-Forwarded-Proto $scheme;`

## ふだんの運用（`~/dandori-olivia/server` で）

| やりたいこと | コマンド |
|---|---|
| 画面・3_サーバー・SQL を直した | `main` に push するだけ（GitHub Actions が配備） |
| 手で入れ替えたい | `./deploy.sh` / SQL は `./deploy.sh --sql ファイル.sql` |
| SQL を1文流す / 対話 | `./db.sh sql "select …"` / `./db.sh psql` |
| 状態を見る | `./deploy.sh --status`（PM2 のプロセス名は `olivia-gateway` のように店舗名付き） |
| ログを見る | `./node_modules/.bin/pm2 logs` または `tail -f logs/*.log` |
| 止める | `./deploy.sh --stop` |

バックアップ：DB は提供元が自動ダンプ + AWS Backup（7日）を行う方針とのこと。
**`server/data/storage/`（ファイル）と `server/.env`（鍵。無くすと全員ログイン不可）** は、こちらで控えを取ってください。

## 困ったとき

- `関数 502`：Deno が初回に esm.sh からライブラリを取得中。1〜2分待って `./deploy.sh --status`。
  それでも駄目なら `tail logs/fn-ai.log`（外向き通信が止められていないか）
- `ログイン 502`：`tail logs/auth.log`。DB の役割 `supabase_auth_admin` のパスワードが `.env` と違うことが多い
- ポートがぶつかる（`EADDRINUSE`）：`.env` の `REST_PORT` などを変えて `./deploy.sh`
- `role "anon" does not exist`：手順 0 がまだ
