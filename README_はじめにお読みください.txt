  このツールは、3つの部品でできています。
  フォルダも、その3つに分けてあります。


  ┌─────────────────────────────────────────────────────────┐
  │  1_画面            ブラウザで動く部分（Netlify に置く）     │
  │  2_データベース     データの入れもの（Supabase に貼る）     │
  │  3_サーバー         AIやLINEの橋わたし（Supabase に置く）   │
  └─────────────────────────────────────────────────────────┘


------------------------------------------------------------------------------
  1_画面   ／  45ファイル
------------------------------------------------------------------------------

  このフォルダの中身を、そのまま Netlify にドラッグすれば動きます。
  ビルド（組み立て作業）は要りません。素のHTML・CSS・JavaScriptです。

  ■ 入口
     index.html      ホール画面（その日の席と伝票）
     login.html      ログイン
     config.js       ★接続先の設定。別のお店に向けるときは、ここだけ書き換え

  ■ 画面ごと（HTML と、同じ名前の JS が対になっています）
     close.html      締め・日報（AIの下書きはここ）
     sales.html      売上
     customers.html  お客さま
     payroll.html    給与
     stock.html      在庫・ボトル
     rides.html      送り
     souji.html      清掃
     wish.html       出勤希望        shiftwish.html  シフト
     docs.html       書類
     admin.html      管理
     theme.html      画面の着せ替え
     teian.html      ご提案
     reset.html      パスワード再設定
     guide.html      使い方ガイド（写真つき・3.4MB）

  ■ 共通で使っているもの
     style.css   見た目ぜんぶ
     ui.js       画面の土台（背景の色から、ボタンの色を作るのもここ）
     menu.js     上のメニュー
     kyotsu.js   よく使う小さな関数
     theme.js    着せ替え
     perm.js     だれに何を見せるか
     pw.js       パスワードまわり
     photo.js    写真
     art.js      背景のかざり
     supabase.js Supabaseの公式ライブラリ（さわらないでください）

  【書き方のきまり】
    画面のJavaScriptは、すべて ES5 で書いています。
    （アロー関数 => ・テンプレート文字列 ` ` ・let/const を使わない）
    古いタブレットやiPhoneでも止まらないようにするためです。
    直すときも、この書き方に合わせてください。

  【ご注意】
    config.js に入っているのは anon キーだけです。これは公開前提の鍵なので、
    ブラウザに置いて問題ありません。
    service_role キーは、ここにも、どのファイルにも、絶対に書かないでください。

     007_demo_data.sql        デモ用のサンプルデータ
     008_sales.sql            売上

     012_bottle.sql           ボトルキープ
     013_payslip.sql          給与明細

  ★ 最後の「だんどり共通_017-027.sql」が、いま未実行のぶんです。
     貼る先は、プロジェクト mfsvfolyrkrpribnwvcl です。
     貼ったあと、つづけてこの1行を実行してください。

        select * from app.demo_fill_all();

  【しくみのメモ】
    ・app スキーマの中に、security definer の小さな関数を置いています。
      app.me() / app.my_tenant() / app.can_store() / app.is_boss() など。
      「誰が」「どのお店を」見てよいかの判断を、ぜんぶここに集めています。
    ・画面から呼べるのは public スキーマだけです。
    ・SQL Editor で実行すると auth.uid() が空になるので、
      デモ投入系は app.◯◯_core(...) と public.◯◯(...) の2段にしてあります。


------------------------------------------------------------------------------
  3_サーバー   ／  5つ
------------------------------------------------------------------------------

  Supabase の Edge Functions です。鍵を使う仕事だけ、ここでやっています。

     ai/            AIの下書き（日報・お礼文）
     line-webhook/  LINEから届いたメッセージの受け口
     photo-search/  写真の検索
     send-outbox/   送信待ちのLINE・メールをまとめて送る
     staff-login/   スタッフのログイン

  【AIについて】
    対応しているのは Gemini / Claude / OpenAI の3つです。
    鍵の名前は、よくある書き方をひと通り受け付けます。
      Gemini … GEMINI_API_KEY / GOOGLE_API_KEY ほか
      Claude … ANTHROPIC_API_KEY / CLAUDE_API_KEY ほか
      OpenAI … OPENAI_API_KEY / OPEN_AI_API_KEY ほか

  【いちばん大事なきまり】
    金額・件数などの数字は、AIに作らせていません。
    すべてデータベース側の関数で確定させてから、AIには文章にしてもらうだけです。
    商談では「AIが日報を書きます」ではなく、
    「下書きを出します。読んで直してから確定してください」とお伝えください。

  直すときの順番（おすすめ）
------------------------------------------------------------------------------

    1. 2_データベース を先に（土台が変わると、画面も直す必要が出ます）
    2. つぎに 3_サーバー

  画面のJSを直したら、貼る前に文法だけ見ておくと安心です。

------------------------------------------------------------------------------
  AWS にまとめる場合
------------------------------------------------------------------------------

  Supabase と Netlify のかわりに、すべてを AWS に置くこともできます。
  データベースは RDS PostgreSQL、ログイン・ファイル・サーバー処理は
  Supabase と同じ部品を AWS の上で動かすので、画面と SQL はそのまま使えます。

  手順は aws/AWS_リリース手順.md を見てください。
  ・SQL Editor のかわりに  ./aws/run-migrator.sh sql "…"
  ・SQL を流したあとは、かならず仕上げ（aws/migrator/post.sql）まで流します
    （./aws/run-migrator.sh schema を使えば自動で流れます）
